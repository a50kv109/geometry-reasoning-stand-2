# Geometry Reasoning Pattern Library (GRPP)

## 1. Назначение каталога

Каталог `docs/patterns/` представляет собой **исследовательский журнал и структурированную библиотеку повторяемых паттернов**, накопленных в ходе экспериментов в среде **Geometry Reasoning Stand (GRS-2)**.

**Geometry Reasoning Pattern Pack (GRPP)** — это не абстрактная энциклопедия формул и не подборка учебных теорем. Это накопитель устойчивых, воспроизводимых методов и структурных закономерностей:

- **Постановки задач**: переход от наглядного чертежа к алгебраическим и топологическим отношениям.
- **Поиска решений**: многоуровневая редукция, сохранение геометрических ветвей, восстановление глобальных объектов по локальным измерениям.
- **Конструктивного моделирования**: принципы бессистемного исключения «магической» геометрии, первичность онтологии над алгоритмом.
- **Анализа динамики и топологии**: сохранение топологической идентичности при 100% изменении координат (`State ≠ Topology`, `Topological Elasticity`).
- **Симметрии и мозаики**: декомпозиция контейнера через максимальный симметричный базис, кинематические контакты и орбиты.
- **Эпистемического контроля**: трехграфовая модель (`Construction ≠ Constraint ≠ Knowledge`), циклы угасания и восстановления (`VALID → INVALID → VALID`, `Vanishing ≠ Delete`).

## 2. Разделение эпистемических понятий

Для предотвращения методологических ошибок в библиотеке строго разделяются четыре категории:

1. **Математическая теорема (Mathematical Theorem)**:
   Формально доказанное общее утверждение, детерминированно верифицируемое ядром стенда или формальной системой (например, теорема Фалеса, формула Карно, теорема Эйлера $d^2 = R(R-2r)$).
2. **Паттерн (Pattern)**:
   Повторяемый способ действия, форма организации графа, эвристика исследования или структурное отношение, доказавшее свою воспроизводимость и эффективность на серии задач. Паттерн *не является* теоремой сам по себе.
3. **Экспериментальная гипотеза (Experimental Hypothesis)**:
   Замеченная в эксперименте параметрическая или качественная регулярность, которая ещё не доказана дедуктивно и требует верификации на более широком классе фигур или граничных условий.
4. **Архитектурный принцип (Architectural Principle)**:
   Инвариант проектирования программного комплекса стенда (например, изоляция онтологии от алгоритмов, разнесение графа построений и графа утверждений).

## 3. Статусы паттернов

Каждый паттерн в библиотеке снабжается строгим квалификационным статусом:

| Статус | Определение |
| :--- | :--- |
| `VERIFIED` | Паттерн многократно подтверждён детерминированными тестами, математическим выводом или серией экспериментов стенда. |
| `INFERRED` | Выведен логически или обобщён из успешных экспериментов, но пока не верифицирован на полном пространстве конфигураций. |
| `CANDIDATE` | Перспективная гипотеза/структура, поддержанная первыми экспериментами, требующая дальнейшей валидации. |
| `EXPERIMENTAL` | Численно или визуально наблюдаемая регулярность в конкретной установке без строгого общего доказательства. |
| `OPEN` | Проблема или паттерн-кандидат с известными контрпримерами или неясными пределами применимости. |

> **Критическое правило:** статус не повышается автоматически. Запрещено называть гипотезу или частное наблюдение универсальным геометрическим законом.

## 4. Жизненный цикл накопления паттернов (Workflow)

Исследовательский цикл работы с библиотекой паттернов организован по простой замкнутой схеме:

```text
       EXPERIMENT (Geometry Stand)
                  ↓
             OBSERVATION
                  ↓
    COMPARE WITH PATTERN LIBRARY
                  ↓
        ┌───────────────────┐
        ↓                   ↓
  EXISTING PATTERN      NEW PATTERN
        ↓                   ↓
  EVIDENCE UPDATE     CANDIDATE PATTERN
        ↓                   ↓
  STATUS RE-EVALUATION      ↓
        └─────────┬─────────┘
                  ↓
         DOCUMENTATION UPDATE
                  ↓
             GIT COMMIT
```

### Критерий добавления:
`NEW OBSERVATION ≠ PATTERN`.
Отдельное единичное измерение остаётся в протоколе эксперимента. Паттерном оно становится только тогда, когда обнаружена **повторяемая структурная схема**, применимая за пределами конкретного экземпляра задачи.

## 5. Архитектурная изоляция

Библиотека паттернов является **документационным и методологическим слоем (Documentation / Research Layer)**:
- Не добавляет runtime-зависимостей в код TypeScript.
- Ядро `src/kernel/` не читает Markdown-файлы во время исполнения.
- API стенда и `GeometryEnvironment` остаются полностью чистыми и неизменными.
