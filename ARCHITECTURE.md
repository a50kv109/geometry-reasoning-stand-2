# Архитектурная Конституция — Geometry Reasoning Stand V2

Документ устанавливает нерушимые правила построения архитектуры, принципы чистоты кода и гарантии математической строгости для разработчиков, преподавателей и ИИ-агентов.

---

## 1. Главный принцип: «Один чертёж — множество клиентов»

В школьном стенде V2 геометрическая истина существует только в одном месте:

```
                  ┌─────────────────────────────────────────┐
                  │              GeometryState              │
                  │   (Единственный источник правды / SSOT) │
                  └────────────────────┬────────────────────┘
                                       │
            ┌──────────────────────────┼──────────────────────────┐
            ▼                          ▼                          ▼
 ┌──────────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
 │   Ученик / Учитель   │   │   Семантический слой │   │      ИИ-Агент        │
 │  Интерактивный холст │   │ Паспорт конфигурации │   │ API среды окружения  │
 │   и учебник (React)  │   │  и проверка теорем   │   │ (Deterministic Gym)  │
 └──────────────────────┘   └──────────────────────┘   └──────────────────────┘
```

- **Интерфейс не считает геометрию:** Компоненты React (`src/components/`, `src/App.tsx`) являются пассивными отображателями. В них запрещено дублировать математические формулы, подсчитывать тригонометрию или подгонять координаты.
- **Агент не меняет правду:** Запросы агента или предположения ученика проверяются через фасад `src/environment/` в изолированной песочнице (`ExplorationRunner`). Ошибочная гипотеза не может повредить чертёж.

---

## 2. The Single Source of Truth: `GeometryState`

Всё состояние доски описывается чистой структурой данных:

```typescript
export interface GeometryState {
  points: Record<string, GeometryPoint>;
  lines: Record<string, GeometryLine>;
  segments: Record<string, GeometrySegment>;
  circles: Record<string, GeometryCircle>;
  activeCluster?: string;
}
```

1. **Никаких теневых состояний:** Запрещено хранить параллельные копии координат в локальных `useState` или глобальных переменных.
2. **Идемпотентность вычислений:** Повторный расчёт по тому же `GeometryState` обязан возвращать строго идентичный результат до последнего знака.
3. **Воспроизводимость:** Любое построение ученика или учителя может быть сохранено в JSON и восстановлено с точностью до пикселя.

---

## 3. The Frozen Baseline Rule (Замороженное ядро)

Математическое ядро аналитической геометрии (`src/kernel/`, `src/engines/constructionCore.ts`) является **замороженным фундаментом**:

- **Запрет на костыли:** Запрещено менять базовые формулы пересечения прямых или окружностей ради «удобства» отдельной теоремы.
- **Чистые функции:** Функции ядра не содержат асинхронных вызовов, сетевых запросов, мутаций глобального состояния или эвристических допущений.
- **Теорема — это предикат, а не хак:** Каждая новая теорема школьного курса оформляется как строгое каноническое правило (`CanonicalRule`), принимающее состояние и возвращающее протокол проверки предусловий (`preconditions`).

---

## 4. Свойство исчезновения (The Vanishing Property)

В реальной геометрии свойство фигуры существует только тогда, когда выполняются его геометрические условия:

- **Вычисление на лету:** Отношения (например, `TANGENT_TO` — касательная, `DIAMETER_OF` — диаметр, `THALES_RIGHT_ANGLE` — прямой угол Фалеса, `PERPENDICULAR_BISECTOR_OF` — серединный перпендикуляр) не приклеиваются к объектам статическими ярлыками.
- **Мгновенное исчезновение:** Если ученик сдвинет точку $C$ с окружности, статус «прямоугольный треугольник Фалеса» мгновенно испаряется из паспорта конфигурации без сохранения ложных следов.
- **Динамическая инвариантность:** Если ученик вращает точку по окружности или меняет её радиус с сохранением условий теоремы, отношение непрерывно остаётся в статусе `VERIFIED`.

---

## 5. Epistemic Read-Only Presentation Layer (Слой наблюдения)

Пользовательский интерфейс построен по принципу прозрачной витрины:

1. Движок формирует `ResearchReport` и `ConfigurationView`.
2. UI принимает эти данные через props и рисует метки, таблицы и подсказки.
3. Ученик и учитель получают мгновенный визуальный отклик (например, значок прямого угла или равенство отрезков) только тогда, когда это подтверждено аналитическим доказательством в ядре.

---

## 6. Методология развития пакетами

Развитие стенда структурировано по логическим узлам школьной и классической планиметрии:

- **Пакет 1 (Треугольник и окружность):** Вписанный треугольник, хорды, центральные и вписанные углы, теорема Фалеса.
- **Пакет 2 (Фундаментальные построения и перпендикуляры):** Серединный перпендикуляр, биссектриса угла, ортогональные касательные из граничной и внешней точек.
- **Пакет 9 (Наблюдение и паспорт):** Семантический паспорт конфигурации, инспектор объектов, визуализация зависимостей.
- **Последующие пакеты:** Замечательные точки треугольника (ортоцентр, центроид, инцентр), вписанные и описанные четырёхугольники, гомотетия и инверсия.

Каждый пакет обязан содержать автономный файл тестов, гарантирующий 100% покрытие перед слиянием в основную ветку.
